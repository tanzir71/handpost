# Handpost architecture

The Electron renderer is an unprivileged React/Vite/Tailwind application. It communicates only through the context-isolated preload API. Every mutating IPC payload is parsed with zod; filesystem, SQLite, notifications, and Playwright remain in the main process.

SQLite migrations run transactionally and idempotently at startup. Posts fan out into independent `post_targets`, so partial multi-platform outcomes are represented without losing the base draft. Media is copied under the app data directory and inspected with ffprobe. Export/import uses a versioned ZIP containing JSON, managed media, and History evidence, never browser profiles or cookies. A local pino log records lifecycle events with credential-shaped fields redacted.

The scheduler ticks every 30 seconds and uses a global concurrency-one queue. Scheduled times are jittered ±90 seconds. It enforces per-platform cooldowns and daily caps, handles startup overdue posts, and records each attempt. Content is rendered and validated before a browser is opened. Publish contexts are headed and off-screen by default, reuse a named persistent profile for the queued batch, and close when the queue becomes idle. Submission is not success: adapters must verify the newest post, capture a permalink and screenshot, or return `unverified` with a diagnostic screenshot.

Each platform adapter has capability, selector, publish, verify, fixture, and contract artifacts. Critical selectors live in the platform directory with platform-specific primaries and generic fallbacks. UI drift saves a sanitized DOM snapshot under `tests/fixtures/_drift`. Captcha/checkpoint detection opens a 24-hour circuit breaker; a second event in seven days requires manual re-enable without erasing the seven-day event history.

The automation inbox (`src/main/inbox/`) watches the Handpost folder described in [`INBOX_PROTOCOL.md`](INBOX_PROTOCOL.md). Each stable file is parsed, validated against the same capability rules as the composer, de-duplicated by its `id`, and either held for review or scheduled through the same queue, pacing, caps, jitter and circuit breaker as a post written in the app. Handpost moves the file to `processed/` or `rejected/` and keeps `receipts/<id>.json` and `handpost.status.json` current so writers can learn what happened.

Inbox internals: discovery is a recursive watcher plus a full rescan every 60 seconds and on resume; a file is read only after its size and modification time have been stable for two seconds. One serial queue handles files and owner actions (approve, reject). Each post is committed in one SQLite transaction (post, targets, managed media copies, `inbox_items` row) before its file moves, so a crash in between turns the re-read file into a harmless duplicate. Receipts follow later changes through a small post-change event emitted wherever post status is recalculated. Posts from the composer, CSV import and the inbox are all written by `src/main/posts/create.ts`. `src/main/inbox/audit.ts` can check that the database, receipts and status file still agree.

Renderer: a token-based design system (`src/renderer/styles/tokens.css`, light/dark/system) and shared components in `src/renderer/ui/`; screens use hash routes so the bundle works from `file://`. In a plain browser an in-memory demo API stands in for the preload bridge (used by `scripts/verify-ui.ts` and the website screenshots).

Live readiness: after a manual login Handpost reads the account's own profile link to store a handle and profile URL, which verification opens. Rehearse fills the real composer, screenshots it and discards it; the submit step is unreachable in that mode. Browser detection finds the installed Chrome or Edge (and version) without launching it; when none is installed, due posts wait as `chrome_missing`. Browser contexts are opened and closed one at a time per platform.

Optional extras: a remote Git source (`src/main/inbox/git-source.ts`, off by default) clones one repository with the system `git` and reads its `inbox/` as a read-only root; `src/mcp/server.ts` is a standalone stdio MCP server that only writes inbox files and reads receipts/status.

Packaging: electron-builder produces a per-user NSIS installer, an unsigned dmg and an AppImage; migrations and `better-sqlite3` are unpacked from the asar, Playwright drives the installed browser (no bundled Chromium), and there is no auto-updater.
